# UniConnect — Full-Stack Development Master Prompt

You are a senior full-stack software architect and developer. Help me build a production-ready public university community platform called **UniConnect**.

## 1. Project Vision

UniConnect is a public, text-first community platform for university students, alumni, faculty, and other members of the university community.

The platform should allow users to:

* Create accounts
* Login securely
* Verify their email
* Reset forgotten passwords through email
* Create professional profiles
* Share ideas
* Ask questions
* Start discussions
* Share resources
* Post jobs and internships
* Find collaborators
* Discover students and alumni
* Connect with other users
* Comment on posts
* Like posts
* Save posts
* Receive notifications
* Report inappropriate content
* Attend/discover events

The platform should NOT be designed as TikTok, Instagram Reels, or a video-sharing platform.

The primary content should be:

* Text
* Images
* Links
* PDFs/documents
* GitHub repositories
* Portfolio links

Do not create a video-first feed or autoplay video system.

# 4. Authentication Workflow

Implement the complete authentication lifecycle.

## Registration

User provides:

* Full name
* Email
* Password
* Confirm password
* University
* Department
* Role
* Batch
* Optional registration number

Roles:

* Student
* Alumni
* Faculty
* Other

After successful registration:

1. Validate all fields.
2. Check whether email already exists.
3. Hash the password securely.
4. Create the user.
5. Generate a secure email-verification token.
6. Send a verification email.
7. Mark the account as unverified.
8. Ask the user to verify their email.

## Email Verification

User clicks the verification link.

The backend:

1. Validates the token.
2. Checks expiration.
3. Marks email as verified.
4. Invalidates the token.
5. Redirects the user to login.

## Login

User enters:

* Email
* Password

Backend:

1. Find user.
2. Verify password.
3. Check account status.
4. Check email verification status.
5. Create secure authentication session/token.
6. Return authenticated user information.

## Forgot Password

User clicks:

`Forgot Password?`

Then:

1. User enters email.
2. Backend generates a secure random reset token.
3. Store only the secure representation of the token if appropriate.
4. Set an expiration time.
5. Send password reset email.
6. Never reveal whether an email exists in a way that enables account enumeration.

The email contains a secure reset link.

Example:

`https://yourdomain.com/reset-password?token=...`

## Reset Password

User opens the reset link.

The backend:

1. Validates the token.
2. Checks expiration.
3. Checks that it has not already been used.
4. Allows the user to create a new password.
5. Hashes the new password.
6. Updates the password.
7. Invalidates the reset token.
8. Invalidates existing sessions if appropriate.
9. Redirects the user to login.

Never send or store plaintext passwords.
